Glosario RAG Production

Referencia — Términos clave del curso

A

Agentic RAG

Arquitectura donde el LLM decide autónomamente si debe recuperar documentos o responder directamente. A diferencia de RAG estándar (siempre recupera), Agentic RAG tiene acceso a herramientas y puede: recuperar, recuperar de nuevo con query reformulada, o responder del conocimiento base del modelo.

B

BM25

Algoritmo de recuperación por palabras clave (sparse retrieval). Mide relevancia por frecuencia de términos y frecuencia inversa de documentos. No entiende semántica, pero es excelente para búsquedas exactas (SKUs, nombres propios, siglas).

C

Chunking

Proceso de dividir documentos largos en fragmentos más pequeños para indexación. Estrategias principales: fixed-size, recursive character, semantic, structure-aware, parent-child. El chunking determina la calidad del retrieval más que cualquier otro componente.

Contextual Retrieval

Técnica de Anthropic (Sept 2024): antes de embeber cada chunk, prepender un resumen generado por LLM de "de dónde viene este chunk". Reduce fallos de retrieval en 49% (solo) y 67% (con reranker).

Cross-encoder (Reranker)

Modelo que evalúa la relevancia de un query-documento juntos, con atención completa entre ambos. Más lento que bi-encoders pero mucho más preciso. Se usa en el segundo stage de retrieval para filtrar los top-100 a top-5.

E

Embedding

Conversión de texto a un vector numérico de alta dimensión (típicamente 768-3072 dimensiones). Textos semánticamente similares quedan cerca en el espacio vectorial. Los embeddings permiten la búsqueda por similitud de coseno.

Evaluation Harness

Framework automatizado para medir la calidad de un sistema RAG. Incluye un dataset de queries con respuestas ground truth, ejecuta el pipeline completo, y calcula métricas como faithfulness, context precision, y answer relevance.

F

Faithfulness

Métrica que mide si la respuesta generada está respaldada por los chunks recuperados. Un score bajo indica alucinación: el modelo generó información que no está en las fuentes. Threshold mínimo en producción: 0.9.

H

Hybrid Retrieval

Combinación de búsqueda densa (vectorial/semántica) con búsqueda sparse (BM25/palabras clave). Se fusionan con Reciprocal Rank Fusion (RRF). Es el estándar de producción en 2026 porque captura tanto coincidencias semánticas como exactas.

Hallucination

Cuando el LLM genera información que no está en el contexto recuperado. En RAG, la mayoría de alucinaciones son síntomas de mala recuperación (chunks irrelevantes o insuficientes), no de mala generación.

L

Long Context

Alternativa a RAG: pasar todo el corpus directamente en el contexto del LLM. En 2026, Claude maneja 200k tokens y Gemini hasta 1M. Más simple que RAG para corpus pequeños. La decisión clave: si tu corpus cabe en contexto, prueba long context primero.

M

MRR (Mean Reciprocal Rank)

Métrica de ranking: si la respuesta correcta está en posición r, el score es 1/r. MRR promedia esto sobre todas las queries. MRR = 1.0 significa que siempre está en primera posición.

R

Recall@K

Porcentaje de chunks relevantes que aparecen en los top-K resultados. Recall@5 = 0.8 significa que el 80% de las veces, el chunk correcto está en los primeros 5 resultados.

Reciprocal Rank Fusion (RRF)

Método para combinar rankings de diferentes fuentes (BM25 + vectorial). Fórmula: score = Σ 1/(k + rank_i). No requiere normalización de scores entre sistemas diferentes.

Retrieval

Proceso de encontrar los chunks más relevantes para una query dada. En producción, típicamente retrieval = hybrid search → top-100 → reranker → top-5.

S

Semantic Chunking

Estrategia de chunking que divide texto basándose en cambios de significado, no en caracteres o tokens. Embedda cada oración, mide similitud entre adyacentes, y crea un boundary cuando la similitud cae. Más costoso pero preserva coherencia semántica.

V

Vector Database

Base de datos optimizada para almacenar y buscar vectores de alta dimensión. Opciones principales 2026: pgvector (startups), Pinecone (managed), Qdrant/Weaviate (self-hosted). La decisión es la menos importante del stack — todas funcionan bien.
